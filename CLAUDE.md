# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Calltrainer is an AI-powered phone conversation trainer: a User calls a simulated conversation partner (a Persona) in a situation (a Scenario), and gets a post-call wrap-up and measured statistics. Domain terms are in `CONTEXT.md`, decisions in `docs/adr/`, the architecture in `docs/arc42.md`. **`docs/codebase-notes.md` is the long-form account of how each feature is built and why** — read the part about the area you are changing before changing it; it is too long to load whole.

## Where things live

Three Python packages beside the frontend, one uv workspace (ADR 0108). Each image carries `shared/` plus its own package and nothing else; `shared` imports neither of the others, and `backend` and `worker` never import each other.

- **Shared** (`shared/`, imported by both processes): `db/` (`models.py`, `session.py`, `seed_data.py`, `migrations/` with `alembic.ini` beside it), `feedback/` (the measuring code: `metrics.py` inventory, `acoustics.py` the only Praat importer, `calls.py`/`stored.py`/`rows.py` the call in and out of the database, `jobs.py` the wrap-up job's status, `queue.py` the queue), `clients/` (the gateway config and `llm.py`), `turn.py` (the Turn timeline), `language_packs.py`, `logging_config.py`, `env.py` (the one reader of settings).
- **Backend** (`backend/`, FastAPI, Python 3.12): `app.py` (lifespan: migrate + seed, backend checks, retention loop), `cors.py`, `api/` (one router per resource; `served.py` is the one place a stored Session's three wire shapes are built; `_loading.py` the shared ownership read), `session/` (the live call: `orchestrator.py`, `prompting.py`, `nudges.py`, `reply_checks.py`, `history.py`, `call_notes.py`, `events.py`), `feedback/` (`readings.py` per-metric explanation/scale/step, `explanations.py`), `clients/` (STT/TTS and their config, the boot check), `db/provision.py` (migrate + seed), `scripts/` (backfills, requeue, retention, checks, stress test, voice audition — each documented under Build / Run below), and the domain modules `library.py` (Persona/Scenario tables), `consent.py`, `deletion.py`, `retention.py`, `focus.py`, `recommendations.py`, `followups.py`, `reversals.py`, `tenants.py`, `authored_text.py`, `documents.py` (with `pdf_text.py`, which reads each PDF in a child process), and the request guards `limits.py` (per-account caps), `body_limit.py` and `gunicorn_worker.py`.
- **Worker** (`worker/`): `__main__.py` (`python -m worker`), `generator.py` (the wrap-up), `segments.py`.
- **Frontend** (`frontend/src/`, React + TS, Vite): `App.tsx` (the training flow's screens), `trainingFlow.ts` (the pure transition table — `advance` is the only caller of `setScreen`), `routes.ts`, `protocol.ts` (the wire types), `config.ts` (the runtime `/config.js`). One module per resource for API calls: `sessions.ts`, `scenarioLibrary.ts`, `personas.ts`; `api.ts` is transport only. Hooks in `hooks/` (the live call: `useLiveCall`, `useBargeIn`, `useSessionSocket`, `useStreamedAudioPlayback`), pure logic in `utils/` (`metrics.ts` is the one record of a metric's display facts; `reportOutline.ts` decides what the feedback page and its PDF say; `pdfDocument.ts` the shared PDF chrome), one stylesheet `index.css`. The image's nginx config and entrypoint are in `frontend/docker/`.
- **Tests** beside each package (`shared/tests/`, `backend/tests/`, `worker/tests/`); the traceability matrix is `docs/testing.md`.
- **Root**: only what all three share — `Dockerfile` (every image), `dev-compose.yaml`, `pyproject.toml`/`uv.lock` (the workspace, the dev group, the pytest/flake8/pylint config), `.env.example`, `keycloak/`, `scripts/build-and-push.sh`, the docs.

## Traps and invariants

Each of these has broken something before or would break it silently. The ADR named carries the reasoning.

- **Consent gates storage** (ADR 0066): `consent.py` answers, inside the write transaction, under a per-subject advisory lock; it **fails closed**. No consent → no stored Session → no wrap-up, history or follow-up; the call still runs.
- **Spoken content is never logged** — not the transcript, not the Persona's synthesized text, at any level; log lengths. `backend/tests/test_transcript_logging.py` pins it.
- **The audio is never stored** (ADR 0048): a new acoustic measurement cannot be backfilled. Only metrics derived from stored text or stored figures can (`backend/scripts/backfill_*`).
- **No backups exist.** Whoever adds them must add a retention policy to ADR 0066 in the same change.
- **Deletion goes through `deletion.remove`** (ADR 0102), which owns the order; the consent log is never deleted (ADR 0068). Say "your trainings are deleted", not "all your data".
- **No figure carries a target, score or judgement** (ADR 0004/0051/0065). The two traffic lights follow ADR 0078's seven conditions — read it before adding a third. Nothing is measured against the Persona. `loudness` is never compared across calls.
- **Ownership answers 404, never 403** (ADR 0031/0050); the client sees `extern_id`, never a primary key. The one 403 is the role gate below, which is about the caller, not a resource.
- **Model work needs the role and stays under the caps** (ADR 0109): `require_user` requires the *client* role `calltrainer-user` (403 without it; the socket's handshake refuses with `not_admitted`), and the SPA shows `NoAccessView` instead of the app. The per-account caps in `backend/limits.py` (open calls, call length, turn audio, hourly PDF and draft budgets) are counted in the backend's **one** gunicorn worker process — a second would double them; routes read them as `limits.X` so the test suite can reset them per test. FastAPI reads a declared body *before* it resolves the auth dependency, so a route taking an upload parses `request.form()` itself (`/api/scenarios/document`), and `body_limit.py` caps every body first. A PDF is only ever read through `pdf_text.read_pdf` (a child process, killed after 30 s) — pypdf on the event loop froze every live call.
- **What the model never reads**: a Scenario's `briefing`, a reverse's `reverse_brief`, `scenario.category`, and the purpose of a follow-up (ADR 0045/0054/0069/0070/0072). Authored text is sanitised at the write boundary (ADR 0059).
- **The provision sweep deactivates only seed rows** (`created_by IS NULL` on `AuthoredContent` tables): without that guard every User's Scenarios would be deactivated at the next boot. `backend/tests/test_seed.py` pins it.
- **KugelAudio's pooled socket**: never leave a `stream_async` short of its `final` frame, and one request at a time (`_pooled_request`, `_pool_lock`, ADR 0044). There is no TTS fallback (ADR 0103).
- **English schema and wire** (ADR 0026/0057/0061); German only in user-facing content. Note `status` means the Session's outcome on the listing and the wrap-up job's status on the detail route.
- **Transactions** (ADR 0099): a domain function takes the open session and never commits; its caller opens the scope. `session_scope()` is synchronous — call it from async code via `asyncio.to_thread`; nothing blocking on the event loop that streams audio.
- **The turn loop imports nothing from the analysis (`shared/feedback/`, `backend/feedback/`, `worker/`) but `acoustics`** and never the ORM; `backend/tests/test_module_dependencies.py` pins it, along with the package boundaries above. `orchestrator.py` sits just under pylint's 1000-line ceiling on purpose.
- **The wrap-up is queued by name** (`JOB_FUNCTION = "worker.generator.generate_feedback"` in `shared/feedback/queue.py`), so the backend never imports the worker. Renaming or moving the generator fails every job in the worker while everything else looks healthy; `worker/tests/test_job_name.py` pins it.
- **Every setting is required and read through `shared/env.py`** (ADR 0106): no defaults in the code, any setting can come from a file as `NAME_FILE`, `CORS_ORIGINS` is the one optional one. Never read a setting with `os.environ` directly. The test fixtures take the database server from the sourced `POSTGRES_URL` and then claim it and `REDIS_URL` with unusable values, so a stray `session_scope()` cannot reach the development database (`shared/tests/test_database_isolation.py`).
- **Logs go to stdout only** (ADR 0105): `LOG_FORMAT=json` in the images, `pretty` locally; there is no log file.
- **Frontend live call**: `useBargeIn` reads socket and playback through a latest-value ref because `useMicrophoneVAD` wires its callbacks once; dropping `interrupt()`'s return silently corrupts the transcript. Reaching the call screen requires the `callAccepted` event.
- **The SPA and the API are two hosts in deployment** (ADR 0107): the backend allows `CORS_ORIGINS` (`backend/cors.py`), the SPA prefixes every request and the call's socket with `apiUrl` from `/config.js`. Locally Vite proxies `/api`, `/ws`, `/health`, so there is one origin and no CORS. A response header the SPA reads must be in `expose_headers` (only `Content-Disposition` today). The frontend image's nginx rules (`frontend/docker/default.conf`) are covered by no test; its `render-config.sh` also writes the Content-Security-Policy, whose `connect-src` names the API (and its socket) and Keycloak — a new host the SPA talks to has to go there, or the browser blocks it (ADR 0109). nginx's `mime.types` has no `.mjs`; `default.conf` adds it, without which the VAD's onnxruntime glue is refused and no call can take turns. Keycloak always redirects to the SPA's origin; `ReturnToRequestedPage` navigates through the router, since `history.replaceState` is invisible to it.
- **UI rules**: never nest a `<button>` in an `<a>`; `--color-brand-accent` is for the wordmark only (below 4.5:1); one `index.css`, deliberately not split (rule order decides 53 shared classes) and guarded by `stylesheet.test.ts`.
- **A metric's display facts are one private record** (`utils/metrics.ts`); `MetricKey` is pinned to the backend inventory by `shared/tests/test_metrics.py`, so adding a metric fails until it is described. Every active metric needs an explanation in `feedback/readings.py`/`explanations.py`.
- **Follow-up and reverse stay two routes** (ADR 0100); `backend/tests/test_followup_scenario.py` and `backend/tests/test_reverse.py` are the same shape on purpose.
- **Focus goals are a setting, not training data** (ADR 0076): no consent guard, and `deletion.py` never touches them.
- **Deployment is the DiReKT Hetzner host**, not the university server ADR 0020 describes, and its compose file lives in `direkt-infrastructure` (`public/calltrainer/compose.yml`), not here. The privacy statement still awaits review by the data protection officer.

## Build / Run

The apps run on the host; `dev-compose.yaml` runs only what they talk to (the dataplatform's model). Nothing here uses `docker compose up` for the apps.

- Setup: `uv sync` (the whole workspace plus the dev group, on the Python in `.python-version` — **3.12**: on 3.14 SQLAlchemy 2.0.36 cannot resolve `Mapped[int | None]` and every database import dies with a `TypeError` that looks like a broken model), `cd frontend && npm install`, then `cp .env.example .env`, fill in the two API keys, and `source .env` in every shell you start a process from. The `export`s are load-bearing.
- Backing services: `docker compose -f dev-compose.yaml up -d` — Postgres on `localhost:15433`, Redis on `16379`, Keycloak on `18081`, all loopback-only, with fixed dev credentials that match `.env.example`. `down` keeps the data, `down -v` wipes it. The ports are shifted so they clash neither with local installs nor with the dataplatform's (15432, 18080).
- Backend: `uv run uvicorn backend.app:app --reload` (port 8000). Worker: `uv run python -m worker` — RQ forks per job, which works on Linux and macOS (with `OBJC_DISABLE_INITIALIZE_FORK_SAFETY=YES`, set in `.env.example`, or every job aborts) but not on Windows; run the worker image there. If the worker is down, calls still work and wrap-ups queue.
- Frontend: `npm run dev` (port 5173) for everything but the call, or `npm run build:watch` plus `npm run preview` (port 8391, the production build) for anything touching the call — see the VAD note below. Both proxy `/api`, `/ws` and `/health` to `localhost:8000` and serve `/config.js` from the shell's `OIDC_ISSUER` (`vite.config.ts`, the same shape `frontend/docker/render-config.sh` writes in the image). Restart Vite after changing `.env`. 5173 and 8391 are the two redirect URIs the dev realm allows. `backend/app.py` switches off FastAPI's `/docs`, `/redoc` and `/openapi.json`, which would otherwise publish every route's shape without a login.
- Turn-taking uses Silero VAD in-browser (`@ricky0123/vad-web` + `onnxruntime-web`, ONNX+WASM); the `predev`/`prebuild` hooks and `build:watch` (`frontend/scripts/copy-vad-assets.mjs`) copy its ~15MB of runtime assets into `frontend/public/vad/` (gitignored, regenerated on every run — not tied to `npm install`, since the Docker build's `npm ci` layer runs before the rest of the source, including this script, is even copied into the image). Known gap: this fails under `npm run dev` specifically — Vite 5's dev-server import-analysis 500s on onnxruntime-web's dynamically-imported `.mjs` WASM glue (a dev-only Vite/onnxruntime-web interaction, unresolved so far). The production build is unaffected — use `build:watch` + `preview` when testing VAD/turn-taking changes.
- Settings (ADR 0106): every variable in `.env.example` is required and read through `shared/env.py`; any can be given as `NAME_FILE=/path` instead, which is how the deployment hands over its secrets. The worker needs only `POSTGRES_URL`, `REDIS_URL`, `DIREKT_URL`, `DIREKT_API_KEY`, `LLM_MODEL` and `LOG_FORMAT`; STT, KugelAudio and `OIDC_ISSUER` are the backend's. The database is one `POSTGRES_URL`, whose password an optional `POSTGRES_PASSWORD[_FILE]` replaces (one secret for the app and the Postgres container). `OIDC_ISSUER` is read by the backend and served to the SPA under the same name, because one issuer under two names is a pair that can disagree and every request then 401s. The three model names are settings on purpose (ADR 0103). Do not add a variable for a value nobody changes — the Keycloak client id (`oidcConfig.ts`) and the token audience (`backend/auth.py`) are constants.
- Dependencies: each package's `pyproject.toml` lists what it imports (`shared/`, `backend/`, `worker/`); the root one holds the dev group and the tool config. Add a dependency to the package that imports it, then `uv lock`. The images install one package's closure each (`uv sync --locked --package calltrainer-backend`), so a dependency in the wrong `pyproject.toml` fails in the image, not on your machine.
- Images (ADR 0108): one root `Dockerfile`, one target each — `docker build --target backend|worker|frontend .` — amd64 only, because praat-parselmouth ships no Linux aarch64 wheel. `scripts/build-and-push.sh [frontend backend worker]` builds and pushes them as `registry.internal.efre-direkt.de/calltrainer-{frontend,backend,worker}`, tagged with the `v*` git tag on HEAD **and** `latest`; it refuses to run unless HEAD carries a `v*` tag that has been pushed. It builds with a buildx `docker-container` builder and `--provenance=true`, because WUD only follows a digest that is an OCI index — a plain `docker push` of `latest` would never be picked up. Needs bash 4 (`brew install bash` on macOS). The Python images set `LOG_FORMAT=json` and run as a non-root user; the frontend image's `render-config.sh` refuses to start without `OIDC_ISSUER`.
- Deployment: `direkt-infrastructure/public/calltrainer/compose.yml` (Traefik routers for `calltrainer.efre-direkt.de` and `calltrainer-backend.efre-direkt.de`, WUD labels, Docker secrets, its own Postgres and Redis). WUD pulls a new `latest` within the hour; nothing is deployed from this repository. The steps — secrets, the real realm's client, audience mapper and Organizations — are in `docs/deployment.md`.
- Keycloak (ADR 0009): `dev-compose.yaml` starts a local Keycloak on `http://localhost:18081` and imports `keycloak/direkt-realm.json` (client `direkt-calltrainer`, dev users `alice`/`bob`/`carol`/`dave`, password = username). `alice`, `bob` and `carol` hold the client role `calltrainer-user` (ADR 0109); `dave` holds none and belongs to no Organization, to see the "nicht freigeschaltet" screen. The realm has Organizations switched on — `company-a` (`alice`, `bob`) and `company-b` (`carol`) — and the client carries the built-in `organization` client scope as a *default* scope, so the token says `"organization": ["company-a"]` and the dev users resolve to those tenants (ADR 0060: the alias is `tenant.extern_ref`). Only `default` is seeded; `backend/tenants.py` creates a company's row the first time its alias arrives, named after the alias. Default, not optional: the SPA does not ask for the scope, and as a default one Keycloak leaves the claim out entirely for a member of several Organizations, which the backend reads as `default` too. Verified against a throwaway Keycloak 26.7 import: Organizations and members survive the import, and the claim is a list of aliases, or a map alias → attributes once the mapper adds attributes or the id — `backend/auth.py` reads both. Membership is the security boundary (a member reads the company's shared Scenarios), and it is admin-managed; there is no user attribute to guard any more. Each dev user's `id` is pinned in the JSON, so a re-import keeps the same `sub` and authored Scenarios (`scenario.created_by`, ADR 0058) are not orphaned — Keycloak's realm JSON rejects unknown keys, so that rationale lives here, not in a comment field. Edit the JSON → drop the volume to re-import: `docker compose -f dev-compose.yaml rm -sf keycloak && docker volume rm direkt-calltrainer-keycloak-data` — Keycloak then mints fresh signing keys, invalidating the browser session, but `apiFetch` catches the resulting 401 and redirects to login. The backend on the host reaches the realm under the issuer's own name, so there is no separate JWKS URL. Keycloak admin console: `admin`/`admin`.
- There is no LLM mock any more — `scripts/mock_llm_server.py` was removed in commit 113394f and never replaced, so anything touching STT/LLM/TTS needs a reachable `DIREKT_URL`. To exercise the wrap-up generator without one, stub `shared.clients.llm.complete`.
- The scripts are modules: `uv run python -m backend.scripts.<name>` on the host (with `.env` sourced), `docker compose exec calltrainer-backend python -m backend.scripts.<name>` on the server, where neither Postgres nor Redis is published.
- Checking the pipeline backends: `python -m backend.scripts.check_backends` fires one minimal real request at each configured STT/LLM/TTS backend and logs OK/FAIL per step (exit 0 only if all pass) — three checks, one per leg, since there is one backend each. The app runs the same check (`backend/clients/health.py:check_backends`) at startup from the `lifespan` handler — a dead model is logged as `Startup check: <STEP> FAILED` but does not stop the app from booting.
- Every service in the deployment carries `restart: unless-stopped`. Without it a Docker restart or a crash leaves a container down, and on the **worker** that is silent — calls keep working and wrap-ups simply never appear, which is exactly how a dead worker went unnoticed for hours. If wrap-ups are missing, `docker compose ps -a` first.
- Retention: `python -m backend.scripts.apply_retention` lists what is past the six-month period, `--apply` deletes it. No Redis needed. The app sweeps daily by itself; this is for checking the period before it bites or clearing a backlog after downtime.
- `python -m backend.scripts.inspect_pressure_segments [--session <extern_id>] [--transcript]` reads back how the wrap-up split each stored call into demanding stretches and the rest (ADR 0081). Read-only, no model and no Redis. It exists because the one thing about that feature no test can answer is whether the *marks* are any good: a run where every Persona line is marked, or none across a dozen calls, means the two stretches are not two, and the screen looks entirely healthy either way. The `Befund` column separates `none-pressing` (judged, nothing pushed) from `unjudged` (the model dropped the key) and `no-facts` (recorded before ADR 0081, so nothing can ever be measured for it).
- `python -m backend.scripts.stress_db` load-tests the schema through the application's own write and read paths (`persist_session`, the wrap-up poll's eager-loaded read) against a throwaway database it creates, migrates and drops on the server `POSTGRES_URL` names; it never touches that URL's own database. Its synthetic subjects are granted consent while it provisions — without that every write is refused (ADR 0066), which is how the script once reported a throughput made of refusals with exit code 0. A write that stores nothing now counts as a failure.
- `python -m backend.scripts.backfill_opening [--apply]` re-reads F-63's Gesprächseinstieg on **stored** Sessions with the current patterns. The odd one out among the backfills: every Session already carries an opening, so this rewrites one rather than filling a gap — which is what a widened pattern needs, since a call recorded before it keeps saying "nicht erkannt" forever otherwise. Only the three parts are rewritten; `pace_ratio` is acoustic, the recording is gone (ADR 0048), and the stored value is carried over untouched. A Session whose parts come out as they already are is skipped and not reported, so a second run after `--apply` says nothing.
- `python -m backend.scripts.backfill_closing [--apply]` computes F-65's Gesprächsabschluss (ADR 0089) for Sessions stored before it existed. No Redis and no model, idempotent, and it skips a Session with fewer than three user utterances exactly as the live path does. Possible because the three parts are read from the stored transcript alone.
- `python -m backend.scripts.backfill_run_length [--apply]` computes F-53's Sprechlänge am Stück for Sessions stored before it existed. No Redis, no model, idempotent, skips Sessions that already carry the figure. Possible because it divides only figures two other metrics already stored — see the metric's note above; the audio is long gone (ADR 0048).
- Wrap-ups can be regenerated: `python -m backend.scripts.requeue_feedback [--apply]` re-queues every stored Session that has Turns but no Feedback. Nothing is regenerated from audio — the wrap-up is written from the stored Transcript and Measurements (ADR 0049), so a Session from days ago can still be analysed. The job writes the wrap-up and nothing else since ADR 0069's amendment — the Folgeszenario is asked for from its own route, so re-queueing never produces one. On the server it runs inside the backend container, the only place Redis is reachable from.
- Database: the app migrates to head and seeds the reference tables itself at startup (`backend/db/provision.py`, called from the `lifespan` handler), so there is no manual step — a provisioning failure is logged as `Database provisioning failed` and does not stop the app, but the setup endpoints then serve nothing and every Session fails to persist. To do it by hand, `python -m backend.scripts.seed_reference_data`, a thin CLI over the same `provision()`. `shared/db/session.py` reads `POSTGRES_URL` lazily, on the first call to `session_scope()`/`get_engine()`, so importing it never requires an environment. Alembic uses the same `build_database_url()`, so migrations can never run against a different database than the app. Provisioning takes a Postgres advisory lock (`PROVISION_LOCK_KEY` and the `advisory_lock()` context manager in `shared/db/session.py`) twice in sequence, never nested: once in `migrations/env.py` around the migration and once in `provision.py` around the seeding, each on a connection of its own. That is what keeps two backend instances (or the app and the seed script) starting at once from applying the same revision twice *and* from racing `_upsert` into a duplicate-key rollback that would log as `Database provisioning failed`. Do not hold it across both steps — the process would wait on itself, without a timeout. The worker migrates nothing.
- Schema changes: edit `shared/db/models.py`, then `uv run alembic -c shared/db/alembic.ini revision --autogenerate -m "..."` (with `.env` sourced). Constraint and index names come from the naming convention on `Base.metadata` (`shared/db/base.py`, ADR 0053) — never name one by hand, and never remove the convention: without it autogenerate emits unnamed constraints whose `downgrade()` cannot run. Note that `op.create_check_constraint`/`op.drop_constraint` apply that convention *themselves*, so a migration passes the bare name (`status_valid`), never the prefixed one. Every foreign-key column carries `index=True` (ADR 0052); two tests enforce both rules. Alembic does **not** autodetect `CHECK` constraints — those have to be written into the migration by hand. **Always read the generated migration before applying it** — autogenerate adds `NOT NULL` columns without backfilling, which fails on non-empty tables, and it cannot recognise a rename: it emits a drop plus a create, which would destroy stored Sessions. `python -m backend.scripts.generate_erd` draws the ER diagram on demand as `docs/diagrams/er_model.svg` (gitignored, never committed, not part of the docs site) and needs the Graphviz `dot` binary (`brew install graphviz`). Three invariants the database enforces since migration `a7c39e5f21b8`, to be kept in `models.py` and in any migration that touches these tables: `measurement` is unique per (`session_id`, `metric_type_id`, `segment`) since ADR 0081 (it was the first two until then) and `turn` per (`session_id`, `seq_index`) — one set of statistics per Session *per stretch of call*, and a transcript order that does not depend on the server. `segment` is NOT NULL with a real value (`call`) for the whole call rather than a nullable column, because Postgres treats two NULLs as distinct and the whole-call rows would drop out of the constraint that exists to protect them; foreign keys into the reference tables (`persona`, `scenario`, `language`, `metric_type`) carry **no** `ondelete` at all, the nullable ones included — only back-references into rows the Session owns (`feedback_point.turn_id`/`finding_id`) are `SET NULL`; and every timestamp column is `DateTime(timezone=True)` and written exclusively with `datetime.now(UTC)`, never a naive `datetime.now()`, because Postgres would read a naive value in the server's zone and every stored time would shift if the app container's `TZ` ever differed. Column defaults (`active`, `attempts`, `extern_id`) are Python-side only, no `server_default`, so a row inserted from `psql` has to name them.
- Docs site (arc42 + ADRs): `uv run mkdocs serve` (serves on `http://localhost:8000` — stop the backend first, or pass `-a localhost:8001`). `mkdocs build` writes static output to `site/` (gitignored).

- Tests: `source .env && uv run pytest` (config in the root `pyproject.toml`; the suites are `shared/tests/`, `backend/tests/`, `worker/tests/`, each file citing the `F-xx`/`R-xx`/ADR it proves — see `docs/testing.md`). The environment and the database fixtures are `shared/tests/fixtures.py`, which each suite's `conftest.py` registers (and imports first, because it sets the environment the imports read); the pipeline fakes and the backend's write path are `backend/tests/conftest.py`, which the worker's end-to-end tests borrow. Persistence tests create, migrate and drop their own throwaway database on the server `POSTGRES_URL` names (`dev-compose.yaml`'s Postgres) and skip without one — look at the skip count, not only the colour. The migration chain is tested in both directions **on an empty database only** — downgrading past `d7f41c9b3a26` fails on a seeded one, deliberately.
- Frontend lint: `cd frontend && npm run lint` — ESLint with the two React hook rules and nothing else (ADR 0094), also the first step of `npm run build`, so the image build fails on a stale dependency list. A remaining `eslint-disable-next-line react-hooks/exhaustive-deps` is a checked exception and must carry its reason; one that no longer suppresses anything is itself an error.
- Frontend tests: `cd frontend && npm test` (Vitest). Deliberately narrow, rendering no components: the live-call audio races and couplings (`useStreamedAudioPlayback`, `useSessionSocket`, `useBargeIn`, `useLiveCall`, `useTrainingRun`), the pure transition and selection tables (`trainingFlow`, `scenarioSelection`), and the pure functions behind what a screen claims about a person (`utils/progressStats`, `goalMentions`, `segmentStats`, `metrics`, `reportOutline`, …) — pin the sentences the screen says, not lines. `stylesheet.test.ts` fails on a class in `index.css` no component names (runtime-built classes are an allowlist). History rows come from one builder (`src/test/sessions.ts`); jsdom plus hand-written Web Audio/WebSocket fakes in `src/test/setup.ts`. Specs are type-checked with everything else.
- Lint: `uv run flake8` and `uv run pylint backend/ shared/ worker/` (config in `pyproject.toml`; flake8 reads it through `flake8-pyproject`). Both are clean (pylint 10.00) and stay that way; a deliberate exception carries `# pylint: disable=X  # reason`. Alembic revisions are excluded from both. **`duplicate-code` is disabled per file in fourteen files, each saying why** — do not replace them with a global disable or a higher `min-similarity-lines`. Shared pieces already merged: `api/served.py` (a stored Session's wire shapes), `api/_loading.py::SESSION_SUBTREE`, `interruptions.finding_description`, and `backend/scripts/_backfill_cli.py` (each backfill still owns its `main()` and its skip rule).
