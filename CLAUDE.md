# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Calltrainer is an AI-powered phone conversation trainer: a User calls a simulated conversation partner (a Persona) in a situation (a Scenario), and gets a post-call wrap-up and measured statistics. Domain terms are in `CONTEXT.md`, decisions in `docs/adr/`, the architecture in `docs/arc42.md`. **`docs/codebase-notes.md` is the long-form account of how each feature is built and why** — read the part about the area you are changing before changing it; it is too long to load whole.

## Where things live

- **Backend** (`backend/`, FastAPI, Python 3.12): `app.py` (lifespan: migrate + seed, backend checks, retention loop; SPA fallback that never answers `/api`, `/ws`, `/health` or a file-looking path), `api/` (one router per resource; `served.py` is the one place a stored Session's three wire shapes are built; `_loading.py` the shared ownership read), `session/` (the live call: `orchestrator.py`, `prompting.py`, `nudges.py`, `reply_checks.py`, `history.py`, `call_notes.py`, `language_packs.py`), `feedback/` (post-call: `metrics.py` inventory, `acoustics.py` the only Praat importer, `readings.py` per-metric explanation/scale/step, `generator.py` the wrap-up, `calls.py`/`stored.py`/`rows.py` the call in and out of the database), `clients/` (STT/LLM/TTS), `db/` (`models.py`, `migrations/`, `provision.py`, `seed_data.py`), and the domain modules `library.py` (Persona/Scenario tables), `consent.py`, `deletion.py`, `retention.py`, `focus.py`, `recommendations.py`, `followups.py`, `reversals.py`, `tenants.py`, `authored_text.py`, `documents.py`.
- **Frontend** (`frontend/src/`, React + TS, Vite): `App.tsx` (the training flow's screens), `trainingFlow.ts` (the pure transition table — `advance` is the only caller of `setScreen`), `routes.ts`, `protocol.ts` (the wire types). One module per resource for API calls: `sessions.ts`, `scenarioLibrary.ts`, `personas.ts`; `api.ts` is transport only. Hooks in `hooks/` (the live call: `useLiveCall`, `useBargeIn`, `useSessionSocket`, `useStreamedAudioPlayback`), pure logic in `utils/` (`metrics.ts` is the one record of a metric's display facts; `reportOutline.ts` decides what the feedback page and its PDF say; `pdfDocument.ts` the shared PDF chrome), one stylesheet `index.css`.
- **Scripts** (`scripts/`): backfills, requeue, retention, checks, stress test, voice audition — each documented under Build / Run below.

## Traps and invariants

Each of these has broken something before or would break it silently. The ADR named carries the reasoning.

- **Consent gates storage** (ADR 0066): `consent.py` answers, inside the write transaction, under a per-subject advisory lock; it **fails closed**. No consent → no stored Session → no wrap-up, history or follow-up; the call still runs.
- **Spoken content is never logged** — not the transcript, not the Persona's synthesized text, at any level; log lengths. `tests/test_transcript_logging.py` pins it.
- **The audio is never stored** (ADR 0048): a new acoustic measurement cannot be backfilled. Only metrics derived from stored text or stored figures can (`scripts/backfill_*`).
- **No backups exist.** Whoever adds them must add a retention policy to ADR 0066 in the same change.
- **Deletion goes through `deletion.remove`** (ADR 0102), which owns the order; the consent log is never deleted (ADR 0068). Say "your trainings are deleted", not "all your data".
- **No figure carries a target, score or judgement** (ADR 0004/0051/0065). The two traffic lights follow ADR 0078's seven conditions — read it before adding a third. Nothing is measured against the Persona. `loudness` is never compared across calls.
- **Ownership answers 404, never 403** (ADR 0031/0050); the client sees `extern_id`, never a primary key.
- **What the model never reads**: a Scenario's `briefing`, a reverse's `reverse_brief`, `scenario.category`, and the purpose of a follow-up (ADR 0045/0054/0069/0070/0072). Authored text is sanitised at the write boundary (ADR 0059).
- **The provision sweep deactivates only seed rows** (`created_by IS NULL` on `AuthoredContent` tables): without that guard every User's Scenarios would be deactivated at the next boot. `tests/test_seed.py` pins it.
- **KugelAudio's pooled socket**: never leave a `stream_async` short of its `final` frame, and one request at a time (`_pooled_request`, `_pool_lock`, ADR 0044). There is no TTS fallback (ADR 0103).
- **English schema and wire** (ADR 0026/0057/0061); German only in user-facing content. Note `status` means the Session's outcome on the listing and the wrap-up job's status on the detail route.
- **Transactions** (ADR 0099): a domain function takes the open session and never commits; its caller opens the scope. `session_scope()` is synchronous — call it from async code via `asyncio.to_thread`; nothing blocking on the event loop that streams audio.
- **The turn loop imports nothing from `backend/feedback/` but `acoustics`** and never the ORM; `tests/test_module_dependencies.py` pins it. `orchestrator.py` sits just under pylint's 1000-line ceiling on purpose.
- **Frontend live call**: `useBargeIn` reads socket and playback through a latest-value ref because `useMicrophoneVAD` wires its callbacks once; dropping `interrupt()`'s return silently corrupts the transcript. Reaching the call screen requires the `callAccepted` event.
- **The backend serves the SPA** (same origin, no CORS, no `/docs`). Keycloak always redirects to the origin; `ReturnToRequestedPage` navigates through the router, since `history.replaceState` is invisible to it.
- **UI rules**: never nest a `<button>` in an `<a>`; `--color-brand-accent` is for the wordmark only (below 4.5:1); one `index.css`, deliberately not split (rule order decides 53 shared classes) and guarded by `stylesheet.test.ts`.
- **A metric's display facts are one private record** (`utils/metrics.ts`); `MetricKey` is pinned to the backend inventory by `tests/test_metrics.py`, so adding a metric fails until it is described. Every active metric needs an explanation in `feedback/readings.py`/`explanations.py`.
- **Follow-up and reverse stay two routes** (ADR 0100); `tests/test_followup_scenario.py` and `tests/test_reverse.py` are the same shape on purpose.
- **Focus goals are a setting, not training data** (ADR 0076): no consent guard, and `deletion.py` never touches them.
- **Deployment is Hetzner**, not the university server ADR 0020 describes. The privacy statement still awaits review by the data protection officer.

## Build / Run

- Frontend: `cd frontend && npm install && npm run build` (writes to `frontend/dist`, which the backend serves). The Vite dev server (`npm run dev`) is not a supported workflow — it has no backend URL configured (there is no `VITE_API_URL` anymore; the app is always run via Docker) and VAD is broken under it anyway (see next bullet). There is no CORS middleware (the SPA is always same-origin), and `backend/app.py` switches off FastAPI's `/docs`, `/redoc` and `/openapi.json`, which would otherwise publish every route's shape without a login.
- Turn-taking uses Silero VAD in-browser (`@ricky0123/vad-web` + `onnxruntime-web`, ONNX+WASM); `npm run dev`/`npm run build`'s `predev`/`prebuild` hooks (`frontend/scripts/copy-vad-assets.mjs`) copy its ~15MB of runtime assets into `frontend/public/vad/` (gitignored, regenerated on every dev/build run — not tied to `npm install`, since the Docker build's `npm ci` layer runs before the rest of the source, including this script, is even copied into the image). Known gap: this currently fails under `npm run dev` specifically — Vite 5's dev-server import-analysis 500s on onnxruntime-web's dynamically-imported `.mjs` WASM glue (a dev-only Vite/onnxruntime-web interaction, unresolved so far). The production build (`npm run build`, served by the backend) is unaffected — use that path when testing VAD/turn-taking changes.
- Local backend: `uvicorn backend.app:app --reload`
- Docker: `docker compose up --build` (builds the frontend too, via a multi-stage Dockerfile; serves on `http://localhost:8391` — a deliberately non-standard host port, mapped to the container's 8000, set in `compose.yaml`). Add `--watch` to pick up code changes automatically (`develop.watch` in `compose.yaml`): backend edits are synced into the running container and the app restarted, without a full rebuild; frontend edits and `requirements.txt` changes trigger a rebuild instead. To restart from scratch: `docker compose down` → `docker compose build` (add `--no-cache` if a frontend change is not showing up) → `docker compose up`. Postgres and the Keycloak session survive that. To re-import `keycloak/direkt-realm.json`, also drop the Keycloak volume first (`docker volume rm direkt-calltrainer-keycloak-data`) — Keycloak then mints fresh signing keys, invalidating the browser session, but `apiFetch` catches the resulting 401 and redirects to login. `docker compose down -v` wipes Postgres too. The Python base image is **pinned to 3.12**, not `python:3-slim`: that floating tag had already moved to 3.14, where SQLAlchemy 2.0.36 cannot resolve the `Mapped[int | None]` annotations and every database import dies.
- Deployment: `docker compose -f compose.yaml -f compose.prod.yaml up -d --build` — the override drops the local Keycloak and its `localhost` issuer (which `compose.yaml` pins in `app.environment`, where it beats `.env`), publishes nothing but Caddy on 80/443 (`deploy/Caddyfile`, TLS for `CALLTRAINER_DOMAIN`; HTTPS is required because the browser grants the microphone only in a secure context) and caps Docker's logs. Needs Compose ≥ 2.24.4 for `!reset`/`!override`. The steps around it — the real realm's client, audience and `tenant` mappers, the pre-deploy `pg_dump` — are in `docs/deployment.md`.
- Copy `.env.example` to `.env` and fill in real values before running — `.env` is gitignored and read via `env_file` in the compose file, and by Vite (`envDir` at the repo root) for `OIDC_ISSUER`, which the SPA reads under the backend's own name through a widened `envPrefix` in `vite.config.ts`, because one issuer under two names is a pair that can disagree and every request then 401s. **`.env` holds only what is secret or differs between development and deployment** — the two API keys, `POSTGRES_PASSWORD`, `OIDC_ISSUER`, `DIREKT_URL` and the deployment-only `CALLTRAINER_DOMAIN` — **plus the three model names**, kept there on purpose (ADR 0103); everything else that is the same everywhere is a constant in the code (the Keycloak client id in `oidcConfig.ts`, the Postgres role/database, the Redis address) and `docs/deployment.md` lists where. Do not add a variable for a value nobody changes.
- Keycloak (ADR 0009): `docker compose up` starts a local Keycloak on `http://localhost:18081` and imports `keycloak/direkt-realm.json` (client `direkt-calltrainer`, dev users `niklas`/`mathias`/`eberhard`, password = username). Each dev user carries a `tenant` attribute (`niklas`/`mathias` → `solox`, `eberhard` → `appollo`) that the `direkt-calltrainer tenant` protocol mapper puts in the token, so they resolve to those tenants (ADR 0060). The realm's user profile **declares `tenant` as a managed attribute with `view`/`edit` restricted to `admin`**, and the unmanaged policy is `ADMIN_EDIT` rather than `ENABLED`. That is load-bearing, not tidiness: ADR 0060 rests on the claim being something an admin sets, and `ENABLED` makes unmanaged attributes writable in the *user* context — an account able to set its own `tenant` picks its own company and reads another one's shared Scenarios. Declaring it takes the question away from the policy entirely. Verified against a throwaway Keycloak 26 import: the attribute survives, arrives in the token, is `edit: ["admin"]` in the served profile, and an admin can still set it. Each dev user's `id` is pinned in the JSON, so a re-import keeps the same `sub` and authored Scenarios (`scenario.created_by`, ADR 0058) are not orphaned — Keycloak's realm JSON rejects unknown keys, so that rationale lives here, not in a comment field. Edit the JSON → wipe the volume to re-import: `docker compose down -v` (or `docker volume rm direkt-calltrainer-keycloak-data`). `KC_HOSTNAME` pins the token issuer to `localhost:18081`; the app container reaches the realm's keys over the compose network via `OIDC_JWKS_URL` (`backend/auth.py`). Keycloak admin console: `admin`/`admin`. For a host-only `uvicorn` run, point `OIDC_ISSUER` at the same URL and drop `OIDC_JWKS_URL` (the host can reach `localhost:18081` directly).
- There is no LLM mock any more — `scripts/mock_llm_server.py` was removed in commit 113394f and never replaced, so anything touching STT/LLM/TTS needs a reachable `DIREKT_URL`. To exercise the wrap-up generator without one, stub `backend.clients.llm.complete`.
- Checking the pipeline backends: `python scripts/check_backends.py` fires one minimal real request at each configured STT/LLM/TTS backend and logs OK/FAIL per step (exit 0 only if all pass) — three checks, one per leg, since there is one backend each. The app runs the same check (`backend/clients/health.py:check_backends`) at startup from the `lifespan` handler — a dead model is logged as `Startup check: <STEP> FAILED` but does not stop the app from booting.
- Every compose service carries `restart: unless-stopped`. Without it a Docker restart or a crash leaves a container down, and on the **worker** that is silent — calls keep working and wrap-ups simply never appear, which is exactly how a dead worker went unnoticed for hours. Note also that `docker compose up -d app` does *not* start the worker (it is not in app's `depends_on`); use a bare `docker compose up -d`. If wrap-ups are missing, `docker compose ps -a` first.
- Retention: `python scripts/apply_retention.py` lists what is past the six-month period, `--apply` deletes it. Works from a host shell (no Redis needed). The app sweeps daily by itself; this is for checking the period before it bites or clearing a backlog after downtime.
- `python scripts/inspect_pressure_segments.py [--session <extern_id>] [--transcript]` reads back how the wrap-up split each stored call into demanding stretches and the rest (ADR 0081). Read-only, host shell, no model and no Redis. It exists because the one thing about that feature no test can answer is whether the *marks* are any good: a run where every Persona line is marked, or none across a dozen calls, means the two stretches are not two, and the screen looks entirely healthy either way. The `Befund` column separates `none-pressing` (judged, nothing pushed) from `unjudged` (the model dropped the key) and `no-facts` (recorded before ADR 0081, so nothing can ever be measured for it).
- `python scripts/stress_db.py` load-tests the schema through the application's own write and read paths (`persist_session`, the wrap-up poll's eager-loaded read) against a throwaway database it creates, migrates and drops; it refuses the database named in `.env`. Its synthetic subjects are granted consent while it provisions — without that every write is refused (ADR 0066), which is how the script once reported a throughput made of refusals with exit code 0. A write that stores nothing now counts as a failure.
- `python scripts/backfill_opening.py [--apply]` re-reads F-63's Gesprächseinstieg on **stored** Sessions with the current patterns. The odd one out among the backfills: every Session already carries an opening, so this rewrites one rather than filling a gap — which is what a widened pattern needs, since a call recorded before it keeps saying "nicht erkannt" forever otherwise. Only the three parts are rewritten; `pace_ratio` is acoustic, the recording is gone (ADR 0048), and the stored value is carried over untouched. A Session whose parts come out as they already are is skipped and not reported, so a second run after `--apply` says nothing.
- `python scripts/backfill_closing.py [--apply]` computes F-65's Gesprächsabschluss (ADR 0089) for Sessions stored before it existed. Host shell, no Redis and no model, idempotent, and it skips a Session with fewer than three user utterances exactly as the live path does. Possible because the three parts are read from the stored transcript alone.
- `python scripts/backfill_run_length.py [--apply]` computes F-53's Sprechlänge am Stück for Sessions stored before it existed. Works from a host shell (no Redis, no model), idempotent, skips Sessions that already carry the figure. Possible because it divides only figures two other metrics already stored — see the metric's note above; the audio is long gone (ADR 0048).
- Wrap-ups can be regenerated: `docker compose exec app python scripts/requeue_feedback.py [--apply]` re-queues every stored Session that has Turns but no Feedback. Nothing is regenerated from audio — the wrap-up is written from the stored Transcript and Measurements (ADR 0049), so a Session from days ago can still be analysed. The job writes the wrap-up and nothing else since ADR 0069's amendment — the Folgeszenario is asked for from its own route, so re-queueing never produces one. Must run inside the container: Redis is not published to the host.
- Feedback worker: `docker compose up` now also starts `redis` and a `worker` service running `python -m backend.worker`. The worker shares the app's image and database but no request cycle; if it is down, calls still work and wrap-ups simply queue. RQ forks per job, so the worker only runs on Linux — use the container, not a host process, on Windows.
- Database: the app migrates to head and seeds the reference tables itself at startup (`backend/db/provision.py`, called from the `lifespan` handler), so `docker compose up` needs no manual step — a provisioning failure is logged as `Database provisioning failed` and does not stop the app, but the setup endpoints then serve nothing and every Session fails to persist. To do it by hand against a host-side database, `docker compose up -d db` then `python scripts/seed_reference_data.py`, which is a thin CLI over the same `provision()`. The seed script calls `load_dotenv()` itself; `backend/db/session.py` does not — it assembles the connection URL in `build_database_url()` lazily, on the first call to `session_scope()`/`get_engine()`, so importing it never requires an environment. There is **no `DATABASE_URL`**: the URL is built from `POSTGRES_PASSWORD` plus optional `POSTGRES_USER`/`POSTGRES_DB` (default `trainer`/`trainer`, `DEFAULT_USER`/`DEFAULT_DATABASE`, the names the `db` service creates — overridable only so the tests and `stress_db.py` can aim at a throwaway database, and not in `.env`) and `POSTGRES_HOST`/`POSTGRES_PORT`, which default to `localhost:5432` for host-side calls — one place for the password instead of a URL duplicated across `.env` and `compose.yaml`. Alembic uses the same function, so migrations can never run against a different database than the app; the app and worker containers get `POSTGRES_HOST=db` from `compose.yaml`, which is the only part that differs. Provisioning takes a Postgres advisory lock (`PROVISION_LOCK_KEY` and the `advisory_lock()` context manager in `backend/db/session.py`) twice in sequence, never nested: once in `migrations/env.py` around the migration and once in `provision.py` around the seeding, each on a connection of its own. That is what keeps the app and the worker starting at once from applying the same revision twice *and* from racing `_upsert` into a duplicate-key rollback that would log as `Database provisioning failed`. Do not hold it across both steps — the process would wait on itself, without a timeout.
- Schema changes: edit `backend/db/models.py`, then `alembic revision --autogenerate -m "..."`. Constraint and index names come from the naming convention on `Base.metadata` (`backend/db/base.py`, ADR 0053) — never name one by hand, and never remove the convention: without it autogenerate emits unnamed constraints whose `downgrade()` cannot run. Note that `op.create_check_constraint`/`op.drop_constraint` apply that convention *themselves*, so a migration passes the bare name (`status_valid`), never the prefixed one. Every foreign-key column carries `index=True` (ADR 0052); two tests enforce both rules. Alembic does **not** autodetect `CHECK` constraints — those have to be written into the migration by hand. **Always read the generated migration before applying it** — autogenerate adds `NOT NULL` columns without backfilling, which fails on non-empty tables, and it cannot recognise a rename: it emits a drop plus a create, which would destroy stored Sessions. `python scripts/generate_erd.py` draws the ER diagram on demand as `docs/diagrams/er_model.svg` (gitignored, never committed, not part of the docs site) and needs the Graphviz `dot` binary (`brew install graphviz`). Three invariants the database enforces since migration `a7c39e5f21b8`, to be kept in `models.py` and in any migration that touches these tables: `measurement` is unique per (`session_id`, `metric_type_id`, `segment`) since ADR 0081 (it was the first two until then) and `turn` per (`session_id`, `seq_index`) — one set of statistics per Session *per stretch of call*, and a transcript order that does not depend on the server. `segment` is NOT NULL with a real value (`call`) for the whole call rather than a nullable column, because Postgres treats two NULLs as distinct and the whole-call rows would drop out of the constraint that exists to protect them; foreign keys into the reference tables (`persona`, `scenario`, `language`, `metric_type`) carry **no** `ondelete` at all, the nullable ones included — only back-references into rows the Session owns (`feedback_point.turn_id`/`finding_id`) are `SET NULL`; and every timestamp column is `DateTime(timezone=True)` and written exclusively with `datetime.now(UTC)`, never a naive `datetime.now()`, because Postgres would read a naive value in the server's zone and every stored time would shift if the app container's `TZ` ever differed. Column defaults (`active`, `attempts`, `extern_id`) are Python-side only, no `server_default`, so a row inserted from `psql` has to name them.
- Docs site (arc42 + ADRs): `mkdocs serve` (serves on `http://localhost:8000`; the app is on `8391` now, so no clash). `mkdocs build` writes static output to `site/` (gitignored).

- Tests: `pip install -r requirements-dev.txt` then `pytest` (config in `pytest.ini`, suite in `tests/`, each file cites the `F-xx`/`R-xx`/ADR it proves — see `tests/README.md`). **Build the virtualenv on Python 3.12** (`py -3.12 -m venv .venv`): on 3.14 SQLAlchemy cannot resolve `Mapped[int | None]` and collection dies with a `TypeError` that looks like a broken model. The pipeline backends are faked in `tests/conftest.py`, which also claims the `POSTGRES_*` names with unusable values before the backend is imported, so a test cannot reach the real database by accident (`tests/test_database_isolation.py`). Persistence tests create, migrate and drop their own throwaway database on the server from `.env` (`docker compose up -d db`), and skip without one. The migration chain is tested in both directions **on an empty database only** — downgrading past `d7f41c9b3a26` fails on a seeded one, deliberately — so take a `pg_dump` before deploying.
- Frontend lint: `cd frontend && npm run lint` — ESLint with the two React hook rules and nothing else (ADR 0094), also the first step of `npm run build`, so the image build fails on a stale dependency list. A remaining `eslint-disable-next-line react-hooks/exhaustive-deps` is a checked exception and must carry its reason; one that no longer suppresses anything is itself an error.
- Frontend tests: `cd frontend && npm test` (Vitest). Deliberately narrow, rendering no components: the live-call audio races and couplings (`useStreamedAudioPlayback`, `useSessionSocket`, `useBargeIn`, `useLiveCall`, `useTrainingRun`), the pure transition and selection tables (`trainingFlow`, `scenarioSelection`), and the pure functions behind what a screen claims about a person (`utils/progressStats`, `goalMentions`, `segmentStats`, `metrics`, `reportOutline`, …) — pin the sentences the screen says, not lines. `stylesheet.test.ts` fails on a class in `index.css` no component names (runtime-built classes are an allowlist). History rows come from one builder (`src/test/sessions.ts`); jsdom plus hand-written Web Audio/WebSocket fakes in `src/test/setup.ts`. Specs are type-checked with everything else.
- Lint: `flake8 .` and `PYTHONPATH=. pylint backend/ scripts/ tests/` (without `PYTHONPATH=.` pylint reports only import errors). Both are clean (pylint 10.00) and stay that way; a deliberate exception carries `# pylint: disable=X  # reason`. Alembic revisions are excluded from both. **`duplicate-code` is disabled per file in fourteen files, each saying why** — do not replace them with a global disable or a higher `min-similarity-lines`. Shared pieces already merged: `api/served.py` (a stored Session's wire shapes), `api/_loading.py::SESSION_SUBTREE`, `interruptions.finding_description`, and `scripts/_backfill_cli.py` (each backfill still owns its `sys.path`/`load_dotenv` preamble, its `main()` and its skip rule).
